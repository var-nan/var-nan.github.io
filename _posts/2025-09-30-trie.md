Have you ever wondered how your phone's keyboard suggests the next character in the word or how your search engine autocompletes your query almost instantly? While a standard Binary Search Tree (BST) or a Hashmap (Dictionary in Python) can store and retrieve words, the Trie (from Re**Trie**val) is often the unsung hero behind lightning-fast text processing applications. It allows for highly efficient storage and searching of strings.

## What exactly is a Trie?
A Trie is a tree-like data structure used to store dynamic set of strings. Unlike a BST where the nodes store the full key (text), a node in the Trie only stores a character or a prefix of the string. It is also called as Prefix Tree. The position of the node in a Trie defines the key associated with it. The node also stores pointers to the children nodes each corresponding to next element in the word. Every path from the root to a node represents a unique prefix (refer figure below).

## API 
The Trie API typically constists of two fundamental operations, `add (word)` and `search (word)`.

1. `add (word)`: To insert a word, start from the root node and move downward by following the corresponding child pointers for each character. If at any point a required child pointer doesn't exist, create a new node for it and continue the traversal until all characters in the word are processed.

2. `search (word)`: The process is similar to `add`. Start from the root and traverse through the Trie following the child pointers for each character in the word. If a required child pointer is missing at any point, it means the word is not present in the Trie. Only its prefix may exist.


## Implementation

Below is a typical implementation of Trie in C++. I assumed that the alphabet set consists only of lowercase english characters to simplify managing and accessing child pointers. But it can be extended to support additional characters. Hashmaps can also be used instead of pre-defined arrays to store the child pointers.


<sub><sup>I assume the reader knows how to read C-family typed-languages.</sup></sub>
```c++
class Node {
public:
    char letter;
    Node *childs[26];
    bool is_end_of_word;

    Node() = default;
    Node(char c) : letter{c} {}
};

class Trie{
    Node *root;
public:
    Trie(){ root = new Node(); }

    void add(const string& word){
        Node *current = root;
        for (char c : word){
            int char_index = c - 'a';
            // if child not exists, create a new child node.
            if (!current->childs[char_index])
                current->childs[char_index] = new Node(c);
            current = current->childs[char_index];
        }
        // current points to a node that holds last character of word. Mark this node as end.
        current->is_end_of_word = true;
    }

    bool search(const string& word){
        const Node *current = root;
        for (char c : word){
            int char_index = c - 'a';
            // if the child node doesn't exit, this word doesn't exist in the tree.
            if (!current->childs[char_index])
                return false;
            current = current->childs[char_index];
        }
        return true;
    }
};
```

## Why use Trie over BST or a Hashmap.
The advantage of Trie over a BST or a Hashmap lies in prefix matching. Say, you have a set of words $$W$$ and $$|W| = N$$. Given a target word $$w$$ of length $$x$$, answer the question, $$\exists b \in W, Prefix(w,b) = true$$ ? 

In case of BST, the time complexity to answer this is $$O(x \times \log N)$$. $$O(\log N)$$ to find the corresponding node and $$O(x)$$ to verify the prefix match. Similarly, time complexity of this operation with a hashmap is $$O(x \times N)$$.


With a Trie, you can achieve this operation with a time complexity of $$O(x)$$. Just a simple path traversal from root node to leaf.


## Applications
Tries are used in various fields; a popular example is auto-completion. Given a universe $$U$$ and a word $$p$$, you want to find out a set $$V \subseteq U$$ such that $$\forall y \in V, Prefix(p,w) = true $$. I will explain how to design a simple autocompletion system in my next post.

## Path Compression.
The size of the Trie can grow very large at times. There are various optimizations that can be used in the Trie to shorten it. One popular trick is to use path compression. If multiple nodes in the path contain only single child, they can be compressed into a single node. This will reduce the memory usage and improve the search performance. This type of tree is called [Radix Tree](https://en.wikipedia.org/wiki/Radix_tree)

Say we have a set of words (Sai_Ajay, Sai_Avinash, Sai_Nanda, Sai_Nandhan, Sai_Koushi, Sai_Devendra, Sai_Devara). A normal trie will have a depth equal to maximum length of word in the set. In this case, it's 11 (size of Sai_Avinash). But with path compression, the maximum depth can be reduced to 3. (below figure).
